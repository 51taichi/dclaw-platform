# Windows 本地助手交付边界

Windows 本地助手是直接交付给 DClaw 客户的桌面程序。客户不需要了解
Runner、设备协议、能力包、公共 Component 或依赖下载机制；这些内容都是本地
助手与超级专家支持插件之间的内部实现。

## 客户界面

- DClaw 客户端负责首次检测、下载、校验、启动和热更新本地助手。
- “安装成功”必须同时表示新版进程已经启动且悬浮球已经创建；不得把只写入
  EXE、只启动后台 Runner 或只建立设备连接报告为客户侧安装完成。
- 本地助手启动后显示一个独立的置顶悬浮球，而不是只运行无界面后台进程。
- 悬浮球先于服务端连接结果显示；连接过程在后台进行，失败时悬浮球保留并显示
  未连接状态，客户仍能查看已有本地任务和产物。
- 悬浮球状态环和状态点显示待处理、失败、运行中、重连或空闲状态。
- 助手面板的外框、圆角控件和状态圆点统一使用抗锯齿绘制；新增图形控件沿用同一绘制入口。
- 单击悬浮球打开旧版样式的本地助手控制面板（任务、目录、退出）；从“任务”进入任务中心。拖动悬浮球可调整位置。
- 右键悬浮球可以打开本地任务、打开任务目录或退出本地助手。

## 本地任务与产物

任务中心和任务输出详情必须让客户直接看到：

- 调用任务的超级专家；
- 运行中、等待继续、已完成、失败或已取消状态；
- 最近更新时间；
- 本地输出文件及文件大小；
- “打开文件”和“打开所在目录”操作。

任务状态保存在 `%LOCALAPPDATA%\DClawLocalTool\Tasks` 下各任务目录的
`task-state.json`。任务执行协议仍使用任务目录内已有的输入、检查点和结果文件，
可视化索引不得改变能力包协议。输出发现会递归扫描任务目录，但排除输入、凭证、
日志和只读文件绑定，避免把客户选择的源文件误认为生成产物。

## 版本与更新

悬浮球、任务窗口、Runner 和依赖管理属于同一个本地助手 EXE，由
`dclaw.super-agent-support` 插件发布。更新本地助手只需发布新的插件助手版本；
DClaw 客户端无需因为本地助手界面或 Runner 更新而重新发版。
