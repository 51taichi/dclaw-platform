# AIGC Aliyun OSS Storage Design

## Goal

New AIGC Studio generated assets must not consume ECS disk space in production. The first storage provider is Aliyun OSS, configured from the admin console.

## Scope

- Applies to new generated AIGC outputs only.
- Does not migrate historical local assets.
- Does not move user-uploaded reference assets in the first slice.
- Keeps existing AIGC canvas and node behavior unchanged from the user's point of view.

## Architecture

Add an admin-only object storage config API backed by a secret JSON file. The first provider is `aliyun_oss`; it stores endpoint, bucket, access key ID, secret, object prefix, enablement, and signed URL TTL.

A focused object storage module owns config persistence, OSS request signing, upload, and signed read URL generation. AIGC Studio remains the caller: `_save_generated_asset()` asks the storage module whether remote storage is enabled. When enabled, generated bytes are uploaded directly to OSS and only metadata is saved locally.

## Asset Access

Generated assets keep the existing `/api/.../aigc-studio/assets/{asset_id}/file` URL. If the asset metadata says it lives on OSS, the backend returns a redirect to a freshly signed OSS URL. This avoids storing expiring URLs inside canvas JSON.

When a cloud-backed generated asset is reused as a reference image, the backend reads it through a signed OSS URL and converts it to a data URL where existing adapters require that shape.

## Admin UI

Add a new settings page: Object Storage. It contains one Aliyun OSS card with:

- Enable switch
- Endpoint
- Bucket
- Access Key ID
- Access Key Secret, with masked preservation on edit
- Object prefix
- Signed URL TTL seconds
- Optional test button

The page lives under the existing admin settings navigation.

## Error Handling

If OSS is disabled, generation keeps using local storage.

If OSS is enabled but upload fails, the job fails instead of silently falling back to ECS disk. This protects production from filling the ECS disk while making misconfiguration visible.

If a cloud-backed asset cannot be read, `/assets/{id}/file` returns an error and reference conversion fails with a clear message.

## Tests

Backend tests cover config masking, secret preservation, OSS upload signing behavior, generated asset upload without local file creation, redirect for cloud assets, and reference conversion from cloud assets.

Frontend tests cover the new admin page load/save request shape and masked secret handling.
