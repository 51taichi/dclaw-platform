# 管理后台模型定价管理设计

**状态：** 待最终审阅

**日期：** 2026-08-30

**依赖：** `2026-08-25-credit-wallet-billing-design.md`、`2026-08-28-open-api-credit-billing-design.md`

**范围：** 在“积分与计费管理”中建立人民币模型成本、倍数定价、价格同步、Excel 导入导出、版本发布和安全控制能力。

## 1. 背景与目标

当前 OpenAPI 计费要求请求开始前锁定一份已发布且已生效的价格目录。生产数据库中尚无价格目录，因此请求会在供应商和 Agent 被调用前返回 `catalog_not_ready`。

本功能的目标不是简单补一张临时价格表，而是建立可持续维护的价格管理体系：

- 根据当前已启用的模型，按供应商和模型分类生成定价清单；
- 尽可能采用供应商真实结算成本，降低错误定价和亏损风险；
- 管理员主要配置倍数，同时允许在必要时维护单模型成本和售价规则；
- 所有客户界面、管理界面和 Excel 只展示人民币与积分；
- 通过草稿、预检、审核和不可变目录发布控制价格变更；
- 即使价格过期或同步失败，也不能中断已经正常运营的客户调用；
- 对关键计费设置增加独立的管理员密码再验证；
- 生成首份有效目录后消除当前因目录为空导致的 503。

## 2. 明确不做的事项

本期不做：

- 面向国外客户的外币售价或外币账单；
- 把网页抓取结果未经验证直接发布为正式价格；
- 因成本价格过期、同步失败或来源暂时不可用而停用已售模型；
- 允许 Excel 上传后直接覆盖正在使用的价格目录；
- 允许管理员绕过安全底价；
- 让客户请求传入成本、售价、兑换比例或应扣积分；
- 将供应商短期促销价默认视为长期可信成本。

## 3. 核心业务原则

### 3.1 人民币为唯一业务展示货币

后台、客户账单、价格目录导出和导入模板统一使用人民币。固定兑换关系默认为：

```text
1 元人民币 = 100 积分
```

部分供应商的原始报价可能采用美元等外币。系统内部仍须保存原始币种、原价、汇率来源和换算时间，用于准确换算、追溯和审计，但这些信息不进入客户侧展示。管理后台的日常定价视图以人民币成本、人民币售价和积分价格为主；原始外币证据仅在审计详情中受控展示。

### 3.2 连续运营优先

已发布目录是运行时价格权威。价格来源过期、同步失败或汇率源不可用时，系统继续使用最后一份可信且已发布的价格，不得返回 `catalog_not_ready` 或停止客户调用。

新模型在没有可信成本时可以出现在后台清单中，但状态为“不可售”，不得进入新发布目录。已经在售的模型不会仅因价格超过复核周期而被自动下架。

### 3.3 准确成本与安全售价

默认价格参数为：

- 汇率与波动风险缓冲：5%；
- 最低销售倍数：人民币可信成本的 1.3 倍；
- 积分兑换：100 积分/元。

管理员可以提高倍数，但不能将正式售价降到系统计算的安全底价以下。上述参数允许由超级管理员调整，但必须通过计费保险锁、版本化发布和完整审计。

## 4. 总体架构

系统分为五个边界清晰的模块。

### 4.1 模型目录

模型目录从当前已配置且启用的供应商模型中建立定价清单。未启用模型不进入正式发布范围。模型按供应商及以下分类展示：

- 文本/多模态对话；
- 图片生成与编辑；
- 视频生成；
- 音频/语音；
- Embedding 与重排；
- 其他模型。

分类不改变真实计价维度。文本模型可以区分输入、输出、缓存写入和缓存读取 Token；图片可以按张数、尺寸和质量等级；视频可以按时长、分辨率和是否带音频；音频可以按字符、时长或输入输出；Embedding 和重排可以按 Token 或请求量。

### 4.2 可信成本库

可信成本库按模型和计价维度保存只追加、不覆盖的成本快照。每个快照至少包含：

- 供应商、模型、能力和计价维度；
- 原始价格、原始币种和原始计价单位；
- 汇率数值、来源及采集时间；
- 换算后的人民币成本；
- 价格来源类型、证明链接或导入批次；
- 来源有效期、优惠开始与结束时间；
- 验证状态、验证人及验证时间；
- 数据采集器或适配器版本。

聚合平台以实际结算平台为成本权威。例如经百炼或火山引擎调用的模型以该平台对 DClaw 账户的结算规则为准，而不是重复采用模型原厂官网价格。账户折扣、阶梯价和限时优惠必须独立记录，不得丢失适用条件。

### 4.3 定价规则

倍数采用四级继承：

```text
全局默认 -> 供应商 -> 模型分类 -> 单个模型
```

最具体的已配置规则优先。规则作用于模型各自真实的计价维度，不把所有模型粗略折算为统一的“每次调用”价格。

基础计算为：

```text
安全成本 = 人民币可信成本 × (1 + 风险缓冲比例)
人民币销售价 = 安全成本 × 有效倍数
积分价格 = 人民币销售价 × 每元积分数
```

金额计算使用定点高精度小数，不使用二进制浮点数。最终扣费延续计费引擎按计价分量向上取整的规则，避免大量小额调用累积为平台损失。免费模型也必须配置平台最低服务价，以覆盖基础设施和运营成本。

### 4.4 草稿与发布目录

自动同步、手工修改和 Excel 导入都只能产生价格草稿。草稿经过差异预检和人工确认后，才能发布为不可变价格目录。

发布目录固化以下快照：

- 原始供应商价格及币种；
- 汇率及其来源；
- 人民币可信成本；
- 风险缓冲比例；
- 命中的倍数规则及继承层级；
- 人民币销售价和积分价格；
- 来源证明、验证状态和验证时间；
- 发布人、发布时间和生效时间。

新请求使用请求开始时最新生效的目录；运行中的请求继续使用已经锁定的目录。后续修改成本、汇率或倍数不得改变旧请求和旧账单。

### 4.5 风险保护与提醒

确认供应商成本上涨且当前售价可能不安全时，系统允许生成自动保护目录：

- 只允许自动上调，不因供应商降价自动降低客户售价；
- 单次自动涨价上限默认为 20%；
- 同一模型 24 小时内最多自动调整一次；
- 所需涨幅超过 20% 时先上调 20%，继续提供服务，并发出最高级别告警；
- 全局默认值可以被单模型规则覆盖；
- 每次自动判断和发布必须完整审计。

自动保护不依赖管理员在线，但修改或关闭保护规则必须解锁计费设置。

## 5. 价格来源与同步策略

价格来源按以下优先级使用：

1. 供应商官方价格 API 或官方结算数据；
2. 管理员基于官方价格页审核确认的数据；
3. 经过预检和审核的 Excel 导入数据；
4. 上一个已验证的可信价格快照。

默认同步周期为：

- 有官方价格 API：每天检查；
- 百炼、火山引擎等聚合平台：每周检查，供应商适配器可覆盖周期；
- 只有普通价格网页：每周检查，页面变化只能生成待审核候选；
- 人工维护或 Excel 导入：每月提醒复核。

系统每天执行的是到期和风险状态检查，不是每天抓取所有产品官网。管理员可以按供应商调整真实采集周期。

超过 7 天未按其计划完成验证的记录标记“待复核”，超过 30 天标记“高风险”。状态升级只触发提醒和告警，不中断已售模型。具体供应商的周期覆盖后，待复核判断应相对于该供应商计划周期计算，避免把正常的月度人工价格误报为每日同步失败。

同步结果必须先标准化币种、计价单位、阶梯条件和优惠期限，再与当前可信成本比较。单位变化、异常幅度、来源冲突或无法解析的价格不得自动成为可信成本。

## 6. 管理后台信息架构

在“积分与计费管理 → 平台定价”中提供五个区域。

### 6.1 定价总览

展示当前生效目录、模型覆盖率、待审核变更、价格来源状态、待复核记录、高风险模型和自动保护事件。目录为空时显示首次初始化向导，而不是让管理员手工执行数据库脚本。

### 6.2 模型价格

按供应商和分类分组，展示每个模型及计价维度的：

- 人民币可信成本；
- 计价单位；
- 风险缓冲；
- 有效倍数及来源层级；
- 安全底价；
- 最终人民币售价和积分价格；
- 来源与复核状态。

### 6.3 定价规则

分别维护全局、供应商、分类和单模型倍数。页面实时展示继承路径和价格预览。任何低于安全底价的结果均不能保存为可发布草稿。

### 6.4 价格草稿

统一承接自动同步、手工编辑和 Excel 导入。差异视图至少区分新增、上涨、下降、缺失、计价单位变化、低于安全底价和异常涨幅。发布前显示影响模型数、预计售价变化和风险摘要。

### 6.5 历史与审计

展示同步、解锁、修改、导入、预检、发布、自动保护和回滚记录。审计记录包含修改前后值、管理员或系统身份、时间、IP、原因和关联目录版本。

## 7. Excel 导入与导出

Excel 导入必须遵循：

```text
上传 -> 格式校验 -> 差异预检 -> 人工确认 -> 生成草稿 -> 发布
```

上传文件不能直接覆盖正式目录，不能绕过安全底价，也不能通过提供前端计算结果来替代服务端计算。重复导入同一文件或同一批次必须幂等。

导出提供四种用途：

- 当前生效价格；
- 最新可信成本；
- 可重新导入的标准模板；
- 风险与待复核清单。

导入和常规导出只体现人民币。为了便于审计，具有相应权限的超级管理员可以在审计详情中查看内部原始币种证据，但不得将其作为客户报价字段。

## 8. 计费保险锁

平台定价页面默认只读。查看价格、风险、历史和审计不要求再次验证密码；以下操作必须先解锁：

- 修改成本、倍数、安全底价、汇率缓冲或积分兑换比例；
- 修改同步周期和自动保护规则；
- 确认 Excel 导入；
- 发布或回滚价格目录；
- 手工确认价格来源。

只有平台超级管理员可以解锁。管理员输入当前账号密码后，服务端签发仅限计费操作的短期授权，默认有效 15 分钟。授权不得复用普通登录令牌或扩展为其他管理权限。

密码只提交给服务端验证，不在前端持久化。修改密码、退出登录、账号被禁用或权限被撤销时，所有计费授权立即失效。连续验证失败必须限流并形成安全告警。

页面顶部显示剩余解锁时间。授权到期后未提交内容可以保留为前端本地草稿，但服务端拒绝保存和发布，管理员重新验证后方可继续。发布目录和降低安全参数等高风险操作在已解锁状态下仍需要最终确认，但无需重复输入密码。

服务端必须对每一个敏感接口独立验证计费授权，不能依赖前端按钮状态。

## 9. 数据流与运行时行为

### 9.1 正常更新

1. 供应商适配器或管理员提交成本候选；
2. 服务端标准化并验证来源、单位、阶梯和有效期；
3. 候选与当前可信快照产生差异；
4. 管理员在已解锁状态下确认可信成本；
5. 定价引擎根据倍数层级和安全底价生成草稿规则；
6. 预检通过后发布不可变目录；
7. 新请求锁定新目录，旧请求继续使用旧目录。

### 9.2 自动保护

1. 可信来源确认成本上涨；
2. 系统计算维持安全底价所需的售价；
3. 应用 20% 单次上限和 24 小时频率限制；
4. 以系统身份发布仅包含必要涨价的保护目录；
5. 记录审计并向管理员告警；
6. 剩余风险继续展示，服务不中断。

### 9.3 首次目录初始化

当数据库不存在任何已发布目录时，后台向导从已启用模型生成初始化草稿。没有可信成本的新模型不得发布；管理员需要补齐或明确排除。预检确认所有拟售模型均有完整计价规则后发布首份目录。

首次目录发布成功后，同一 OpenAPI 请求应能锁定目录并进入 Agent 调用链，不再返回 `503 catalog_not_ready`。

## 10. 并发、失败与回滚

- 目录发布使用数据库事务和乐观版本校验，避免两个管理员互相覆盖；
- 同一草稿只能成功发布一次，重复请求返回原发布结果；
- 同步服务只有提交候选的权限，无权任意修改或发布正式售价；
- 同步失败、来源失效和汇率服务不可用时保留最后可信目录；
- 回滚通过重新发布目标历史目录的等价新版本完成，不修改历史目录；
- 回滚仅影响新请求，历史调用和账单继续引用原快照；
- 价格目录读取失败时应优先使用已验证的最近可用目录缓存，但缓存必须带目录身份和完整性校验；
- 真正没有任何可用目录的全新安装仍拒绝产生无价格调用，后台必须明确提示完成初始化，而不是自动使用零价或猜测价格。

## 11. 权限与审计

权限边界如下：

- 普通管理员：查看定价总览和非敏感历史；
- 平台超级管理员：解锁后维护、审核、发布和回滚；
- 同步服务身份：写入候选和同步状态；
- 自动保护服务身份：只能在预设限制内生成并发布涨价保护版本。

所有敏感记录保存管理员或服务身份、时间、IP、修改原因、修改前后值、来源证据、草稿和目录版本。审计记录不可由普通管理接口修改或删除。

## 12. 测试与验收

### 12.1 价格计算

- 六类模型及其不同计价维度；
- 四级倍数继承和最具体规则优先；
- 5% 风险缓冲、1.3 倍安全底价和 100 积分/元；
- 高精度小数和分量向上取整；
- 阶梯价、账户折扣、优惠到期和免费模型最低服务价。

### 12.2 同步与连续运营

- 各价格来源优先级和供应商周期覆盖；
- 同步失败、过期价格、汇率失败和来源冲突；
- 已售模型继续使用最后可信目录；
- 无可信成本的新模型不可售；
- 降价只进入审核，不自动降低售价；
- 20% 自动涨价上限和 24 小时频率限制；
- 所需涨幅超过上限时继续服务并产生最高级别告警。

### 12.3 草稿、Excel 与目录

- Excel 格式错误、非法单位、重复批次和缺失字段；
- 导入预检、人工确认和安全底价阻断；
- 草稿并发修改、幂等发布和版本冲突；
- 运行中请求锁定旧目录，新请求使用新目录；
- 历史目录不可变和回滚生成新版本；
- 首次初始化覆盖校验。

### 12.4 安全

- 未解锁、授权过期、密码错误和非超级管理员越权；
- 密码修改、退出和账号禁用使授权失效；
- 密码失败限流和安全告警；
- 前端绕过按钮直接调用敏感接口仍被拒绝；
- 审计记录包含完整前后值和操作者身份。

### 12.5 端到端验收

- 后台按供应商和分类列出所有已启用模型；
- 管理员能够以人民币成本和层级倍数生成并发布首份价格目录；
- Excel 可以导出、导入、预检并生成草稿；
- 已发布目录满足 `status='published'`、`effective_at <= now`、`published_at <= now`；
- 与当前故障相同的 OpenAPI 请求不再返回 `503 catalog_not_ready`；
- 请求能够进入 Agent 和供应商调用链，并使用锁定目录完成积分预留与结算；
- 价格同步故障和价格过期不会中断客户调用。

## 13. 实施边界与顺序

建议按以下顺序实施，避免先做页面却仍无法形成有效目录：

1. 成本快照、规则层级、人民币换算和安全底价领域模型；
2. 草稿、预检、发布、回滚及运行时最近可用目录策略；
3. 首次目录初始化和 OpenAPI 端到端验证；
4. 计费保险锁、敏感接口授权和审计；
5. 管理后台五个区域；
6. Excel 导入导出；
