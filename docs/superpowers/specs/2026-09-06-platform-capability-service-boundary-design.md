# 平台能力开放层与 DClaw Service 单向依赖设计

日期：2026-09-06

状态：核心原则已获用户确认；本文是待审阅的落地设计，不代表代码改造、部署或端到端验收完成。

## 1. 已确认的核心原则

DClaw 是独立完整的产品。超级专家通过受控能力清单使用平台已有功能，不是系统核心运行的前提。

两套接口入口、一套核心业务实现、依赖方向单向：

- 系统接口服务 DClaw 自身页面及既有系统调用方。
- 超级专家能力接口提供能力发现、授权、契约转换、任务归属和结果回传。
- 两种入口均直接调用共享 Service，不通过 HTTP 回调本机页面接口，不复制业务实现。
- 共享 Service 和系统接口不得导入或调用超级专家能力接口、专家任务仓库、陆羽运行时。
- Service 不通过注入一个调用超级专家服务的回调来伪装单向依赖。执行所需的领域规则由系统自身持有。
- 上层适配器可以消费系统通用事件，但事件处理失败不能将已成功的系统操作改成失败。

本设计中的“能力开放层”指面向超级专家的 API/适配模块，不指整个 DClaw 系统。

## 2. 范围与非目标

本轮以现有 AIGC 为首个落地模块，先修正代码依赖和共用业务边界，再验证已有会话、卡片、画布、提交与回传路径。

不实现 MCP、RPA 新开放接口，不新增视频合成执行器，不另建通用工作流引擎，不拆分部署服务，不增加消息中间件。

不修改陆羽 S0–S4，不放宽阶段 Gate、真实素材审核、计费或资源隔离规则。保持普通 Agent 路由和现有签名安装授权机制；“按授权开放”不改变既有签名包整包授权规则。

此前提出的同画布多卡片、素材版本依赖和逐卡审核是后续产品目标。此次边界改造不得宣称已完成这些能力，也不在架构重构中顺带改变现有单卡绑定数据语义。

## 3. 已核对的源码现状

以下为本地源码检查，不等于线上行为验收：

1. `src/qwenpaw/app/routers/super_expert_platform.py` 已有能力命令、安装授权、幂等、任务与事件存储，并非从零建立开放层。
2. 该文件的 `SuperExpertPlatformService` 当前定义在路由模块，创建操作调用 `routers/aigc_studio.py` 中的 `provision_super_expert_aigc_workspace` 和工作流创建辅助函数；能力目录、工作流上下文和审核资产解析也跨路由复用。
3. `routers/aigc_studio.py::_authoritative_workflow_execution_binding` 反向调用 `get_super_expert_platform_service().workflow_node_execution_binding`，用于节点 provider/model/capability 的权威校验。
4. AIGC 画布元数据已有 `super_expert_material_task_id`；工作流蓝图当前保存在专家任务记录内。不能直接删掉上述反向调用，否则会丢失权威执行约束。
5. `app/super_experts/events.py` 已保存绑定事件和审核回执，但其信封要求安装、会话、素材卡片等信息，是开放层事件，不应直接成为 AIGC 核心事件模型。
6. `app/aigc/model_policy.py` 和 `qwenpaw/aigc/workflow_compiler.py` 等已有可复用领域逻辑。复用这些实现，不创建第二份能力判定或工作流编译规则。

工作区存在大量未提交修改，包括模型政策、计费和媒体审核相关工作。本轮实现须保留原修改，不整体覆盖、回滚或夹带发布。

## 4. 方案选择

选择同进程的共享 Service 加薄适配层。

- 不选复制一套专家专用 AIGC：会产生计费、权限和状态规则漂移。
- 不选通过 HTTP 调用自身页面 API：增加会话模拟、网络故障及重复调用成本。
- 不选现在拆成独立服务：对当前目标没有必要，部署与事务复杂度明显增加。

两套入口保持独立契约，底层领域类型只表达用户、画布、节点、工作流、任务与资产，不表达陆羽阶段或专家方法。

## 5. 模块职责与调用边界

### 5.1 系统接口

保留既有路由、请求参数及响应格式。入口从真实登录态解析身份，转换为显式 Service 调用上下文；不把浏览器“当前画布”或模型传入的用户 ID 当权威身份。

### 5.2 AIGC 共享 Service

在 `src/qwenpaw/app/aigc/` 提取当前链路所需的画布/工作流创建、工作流执行约束查询、资产归属解析和任务状态查询。具体文件按领域拆分，不将整个大路由机械搬进一个大 Service。

Service 使用明确的用户/租户资源范围和依赖对象，不依赖 FastAPI Request、HTTPException 或上层接口处理函数。路由负责把领域错误映射成现有 HTTP 错误；开放层映射成稳定能力错误。

共享规则包括资源归属、节点与模型合法性、资产版本、状态迁移及既有计费入口。专家专属权限由开放层额外校验，不能取代核心资源校验。

### 5.3 超级专家能力适配层

将当前路由内的应用编排职责逐步移至 `app/super_experts/`；路由只做入口解析与返回。继续使用已有能力目录、签名安装授权和任务绑定模型。

调用核心前解析并验证安装、用户、原会话和能力版本。核心返回资源 ID 后，开放层建立卡片与业务任务的绑定；不得由模型指定任意物理绑定来取得权限。

专家接口不读取核心私有存储文件，不绕过 Service 复制创建/生成/删除逻辑。内部实现升级由适配层消化；不原样透传核心数据结构、异常和凭据。

### 5.4 应用组装

应用启动层负责组装 Service、存储及事件消费方。不开启超级专家功能时，系统接口和 AIGC Service 应能独立构造和工作。

## 6. 移除反向执行绑定查询而不降低安全性

工作流 provider/model/capability 约束属于 AIGC 工作流执行规则，应在工作流创建时由共享 Service 持久化为系统自己的受信记录，绑定资源所有者、画布、工作流版本、逻辑/物理节点。

系统生成入口读取这份记录验证请求，不再查询专家任务仓库。画布可编辑元数据仅作展示或兼容标识，不能成为受信约束的替代品。受管节点缺少记录或记录不匹配时拒绝执行，禁止退化为信任客户端参数。

已有数据迁移由单独的受信迁移适配器读取旧专家任务、校验实际画布归属和蓝图版本，再经核心导入入口登记约束；它属于部署/迁移工具，不由系统请求路径执行。必须可重复执行、生成逐项报告且不改资产、计费、原会话 ID。

新工作流创建先落核心工作流及执行约束，再绑定专家卡片。后续失败仅能补偿本次新建且未执行的资源；不得删除复用画布或已有成果。跨存储提交使用稳定操作键和可恢复记录，不声称多个 JSON 文件天然具备原子事务。

## 7. 事件与可靠回传

AIGC 核心事件只描述系统事实，如任务完成/失败、资产就绪或资源版本变化，携带事件 ID、类型/版本、所有者范围、资源及版本、操作关联 ID。核心事件不要求安装 ID、陆羽 task_id 或 S 阶段。

开放层通过自己的绑定仓库将事件映射到发起专家和原会话，再生成既有专家事件。普通用户操作没有专家绑定时，不需要制造空的专家任务。

优先使用现有持久化能力：同一系统状态事务记录待投递事件；若存储暂不能做到同事务，必须使用可重入操作记录及状态对账恢复，并覆盖写入与回传之间崩溃的测试。不能只依赖进程内广播。

消费者按事件和目标绑定去重，失败保留待投递状态，重启可补送。回调超时不得重新发起付费生成。卡片可查询平台实际任务状态，不以是否收到某条 SSE 或模型是否说“完成”作为唯一依据。

保留“生成完成、客户提交、专家审核、最终发布许可”之间的区别。审核结论由发起专家产生，绑定实际资产版本；开放层校验来源与绑定后保存，不计算陆羽业务 PASS。导航回原会话不等于提交或通过。

## 8. 兼容与交付顺序

1. 建立现有行为特征测试和依赖边界测试，标注当前反向调用为待消除违例，不通过删校验使测试变绿。
2. 提取最小共享 Service，让系统入口和能力入口调用同一实现；移动代码而非保留两份生产实现。
3. 新工作流采用核心受信执行约束；完成旧工作流迁移验证，再切换系统查询并移除反向调用。
4. 在既有绑定/事件基础上接通可靠事件适配与恢复，保持现有前端契约。
5. 做系统入口、专家入口、禁用专家组件和原会话闭环测试。发布前独立核对其他本地改动，不能把源代码测试通过当成线上验收。

新能力 ID 或不兼容契约必须显式升级并按现有签名授权规则处理；不在原版本下静默改变权限。

## 9. 验收标准

- 静态和运行时依赖测试证明核心 AIGC/系统路由不导入专家接口或专家任务仓库；不采用动态导入或回调绕过检查。
- 系统和专家两种入口使用同一 Service，资源隔离、模型政策、状态及计费行为一致；专家额外授权仍有效。
- 没有专家组件时普通画布/生成路径正常，已登记的工作流执行约束仍能独立校验；缺少约束的受管节点不能被当普通节点放行。
- 不允许跨用户、跨画布、跨节点、跨资产版本调用。普通 Agent 不能靠参数或提示词伪造专家授权。
- 重复命令、相同幂等键不同参数、重复/乱序事件、重启、回传失败均有测试；不重复生成、扣费或推进状态。
- 旧画布和卡片迁移后原链接可恢复，现有成果和审核历史保留；冲突数据报告并隔离，不猜测修补。
- 原任务会话 → 卡片 → 绑定画布 → 制作 → 提交 → 发起专家审核 → 原会话/卡片显示真实结果，按独立集成测试验证。
- 模拟供应商、真实模型审核、真实 AIGC 生成及线上部署分别报告，不能混称已验收。真实付费/外部操作依照既有用户授权，不因重构扩大权限。
- 陆羽 S0–S4 和普通用户既有入口回归保持不变。

## 10. 文档自检结论

设计明确分开系统执行状态、开放层卡片状态和专家业务状态，没有让核心理解 S 阶段。事件适配不构成核心反向调用；工作流约束迁移不删除原有 Gate；当前重构与后续多卡片产品能力分开交付。本文不授权新增制作引擎、对外发布或自动迁移生产数据。
