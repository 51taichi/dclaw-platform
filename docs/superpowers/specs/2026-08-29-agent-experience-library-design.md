# 我的Agent经验库设计

日期：2026-08-29

## 目标

允许登录用户维护绑定到自己名下 Agent 的 OpenAPI 专属知识库，同时保留管理员后台的完整维护能力。管理员端与用户端必须复用同一个前端组件、同一个 API 模块和同一组后端接口，避免两套实现产生行为差异。

本功能在用户界面命名为“我的Agent经验库”。它只调整 OpenAPI 专属知识库的维护入口与授权方式，不改变个人知识库、企业知识库、OpenAPI 调用流程、密封 Agent 规则或 Agent 运行方式。

## 当前问题

OpenAPI 专属知识库的列表、上传、重建索引和删除接口当前位于管理员路由下。普通用户即使是发布对象的 `bound_user_id`，也没有可用的客户端入口和受限接口。

现有数据模型已经同时保存：

- `owner_user_id`：创建和管理 OpenAPI 发布对象的管理员身份；
- `bound_user_id`：OpenAPI 调用实际绑定的用户，也是用户侧经验库的维护主体；
- `knowledge_base_id`：该发布对象独占的知识库标识。

因此不需要新增知识库归属表，只需建立统一的可见性与操作授权策略。

## 方案选择

采用中立、角色感知的统一接口。管理员后台和用户端都迁移到该接口，不让普通用户访问带有 `/admin` 语义的路径，也不维护管理员与用户两套路由。

拒绝以下方案：

- 为管理员和用户分别维护接口：虽然可以复用底层服务，但接口契约容易漂移；
- 放开现有管理员路由给普通用户：接口语义混乱，权限审计不清晰。

## 后端接口

新增统一前缀 `/api/open-api-knowledge`，提供：

- `GET /publications`：列出当前身份可维护的发布对象；
- `GET /publications/{publication_id}/docs`：列出文档；
- `POST /publications/{publication_id}/docs`：上传文档；
- `POST /publications/{publication_id}/docs/{doc_id}/sync`：重建索引；
- `DELETE /publications/{publication_id}/docs/{doc_id}`：删除文档、切片和索引。

列表结果需要包含共享组件展示所需的公开运维字段：

- 发布对象 ID、Public ID、发布标题和状态；
- Agent 或专家团的目标类型、目标 ID 和可展示名称；
- 专属 `knowledge_base_id`；
- 当前调用者在该对象上的维护能力标记。

文档数据结构沿用现有 OpenAPI 知识文档结构，上传、同步和删除响应保持与现有管理员接口兼容。旧管理员知识接口在迁移期可以保留，但前端不再调用；确认没有其他消费者后再单独决定是否移除，不在本次范围内删除旧接口。

## 授权模型

所有授权由服务端根据已认证身份执行，publication ID 仅用于定位对象，不能作为授权依据。

普通用户满足以下条件时可以查看和维护发布对象：

```text
publication.bound_user_id == current_user.id
```

管理员维持当前维护范围，即可维护其管理员 OpenAPI 后台中可见的发布对象。当前实现以 `owner_user_id` 与管理员身份匹配为准，不扩大为任意管理员可操作所有租户数据。

每一个列表、文档读取、上传、重建和删除请求都必须重新校验权限。前端隐藏不构成安全控制。对象不存在或调用者无权访问时统一返回 `404`，避免通过响应差异探测其他用户的发布对象。

权限校验应集中在一个共享服务或授权函数中，路由处理函数不能分别实现条件判断。经验库的数据读写继续使用发布对象的 `knowledge_base_id` 作为隔离键。

## 前端架构

在 dclaw-client 中抽取共享的 `AgentExperienceLibrary` 组件及统一 API 模块。

共享组件负责：

- 加载当前身份可维护的发布对象；
- 按名称搜索和选择发布对象；
- 展示发布状态、Public ID、目标类型和知识库标识；
- 加载文档列表；
- 上传文档、重建单个文档索引和删除文档；
- 展示加载、空状态、单项忙碌和错误反馈。

组件不接收管理员或普通用户布尔参数，也不在浏览器端复制权限规则。两端的差异只来自统一接口返回的可见对象。

管理员 OpenAPI 页面的“专属知识库”页签改用该组件。用户现有“知识库”页面新增“我的Agent经验库”页签并使用同一个组件。个人知识库和企业知识库现有功能保持原样。

## 页面交互

“我的Agent经验库”顶部显示当前用户可维护的 Agent 发布对象。选择项按以下方式展示，名称优先、ID 辅助：

```text
Agent 名称 · 发布名称 · Public ID
```

同一用户拥有多个 Agent 时可以搜索切换；同一 Agent 有多个 OpenAPI 发布对象时分别展示，防止文档误传。禁用的发布对象仍允许维护经验库，但必须显示“接口已禁用”状态。

没有可维护对象时展示引导空状态，说明需要管理员先把 Agent 发布为 OpenAPI 并绑定给当前用户，不展示无效上传入口。

选择对象后展示：

- Agent 名称与发布名称；
- Public ID；
- 启用或禁用状态；
- 专属经验库标识；
- 文档列表与上传按钮。

上传期间禁止重复上传，但不阻塞阅读现有文档。重建索引使用单项忙碌状态，不锁定整张表。删除使用二次确认，并明确文档、切片和索引会一并清理。操作失败时保留当前选择和已加载数据，显示服务端可安全展示的错误信息。

## 数据流

1. 页面挂载共享组件。
2. 组件调用统一发布对象列表接口。
3. 服务端根据当前身份返回授权范围内的对象。
4. 组件选择首个对象或恢复仍可见的上次选择。
5. 组件用 publication ID 加载文档；服务端再次授权并映射到 `knowledge_base_id`。
6. 上传、重建和删除均使用同一 publication ID，并在每次请求中重新授权。
7. 操作成功后只刷新当前对象的文档数据，不重新加载整个页面。

如果刷新后原选择已不再授权，组件清空选择并回到空状态，不继续显示旧数据。

## 错误处理

- `404`：对象不存在或无权访问，清除当前对象并刷新可见列表；
- `401`：交由现有登录失效机制处理；
- `413` 或文件校验失败：保留列表并显示上传限制信息；
- 索引服务失败：保留文档及其失败状态，允许再次重建；
- 网络错误：保留当前可见数据并提供重试入口；
- 并发操作：上传使用页面级上传锁，重建和删除按文档 ID 独立加锁。

## 兼容与迁移

- 不修改 `open_api_publications` 和知识库相关数据库表；
- 不改变现有 `knowledge_base_id`，避免知识数据迁移；
- 管理员前端迁移到统一接口后，其可见范围和操作能力保持不变；
- 用户端只获得绑定对象的经验库维护能力，不获得发布配置、API Key、调用记录或内部 Agent 资产权限；
- 密封 Agent 的提示词、Skill、源码与内部追踪仍不可见，经验库维护不构成资产查看权限。

## 测试策略

后端测试覆盖：

- 管理员可以列出并维护其现有范围内的发布对象；
- `bound_user_id` 匹配的普通用户可以列表、上传、重建和删除；
- 非绑定用户无法枚举或操作对象，越权与不存在均返回 `404`；
- 同一用户多个 Agent、同一 Agent 多个发布对象均正确返回；
- 禁用发布对象仍可维护经验库；
- 权限在列表后发生变化时，后续写操作立即拒绝；
- 删除同时清理文档、切片和索引的现有语义不变。

前端测试覆盖：

- 管理后台和用户页面均渲染同一共享组件；
- 发布对象选择显示 Agent 名称、发布名称和 Public ID；
- 多对象切换加载正确文档；
- 空状态、禁用状态、上传、单项重建和删除确认；
- `404` 后清除无权对象，其他失败保留当前数据；
- 管理员页面现有 OpenAPI 其他页签不受影响；
- 用户个人知识库和企业知识库流程不受影响。

完成后分别运行服务端单元与集成测试、客户端相关组件测试、Lint、格式检查和生产构建。

## 非目标

- 用户创建、启用或禁用 OpenAPI 发布对象；
- 用户创建外部应用或 API Key；
- 用户查看 OpenAPI 调用记录；
- 合并个人知识库、企业知识库与 Agent 经验库的数据；
- 修改密封 Agent 的内部资产访问规则；
- 删除旧管理员知识接口。
