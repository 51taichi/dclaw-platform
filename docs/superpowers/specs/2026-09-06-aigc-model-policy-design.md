# AIGC 创意工作室模型策略设计

## 背景与目标

当前 AIGC 创意工作室从模型注册表读取已配置、已发布、已定价并声明了 AIGC 能力的模型。管理员尚不能在统一入口控制哪些模型对 AIGC 用户开放，也不能分别指定文本、图片、视频和音频节点的默认模型。

本改造在后台“模型”页面的“默认向量模型”下方增加“AIGC 创意工作室模型”模块。管理员可以为四类模型维护有序白名单，并为每类指定一个默认模型：

- 生文模型
- 生图模型
- 生视频模型
- 生音频模型

用户端 AIGC 节点只展示管理员允许且当前有效的模型。模型因供应商、发布、定价或适配器状态变化而失效时，系统动态计算有效默认模型，并在原默认恢复后自动恢复使用原默认。

## 非目标

本改造不修改：

- 供应商适配器及其调用协议；
- AIGC 画布、节点连接和任务数据结构；
- 计费、积分扣减与价格计算规则；
- 历史生成记录和素材数据；
- 图片编辑、参考图、图生视频等子能力的独立策略。这些能力归入图片或视频模型大类。

## 术语与模型分类

策略使用四个稳定分类键：`text`、`image`、`video`、`audio`。

- `text`：所有已配置的普通 LLM 均可作为候选，不要求预先声明 `storyboard`；发布、定价和供应商状态仍决定其是否可选。
- `image`：具有 `text_to_image`、`image_to_image`、`image_edit`、`mask_edit` 或相关图片生成能力的模型。
- `video`：具有 `text_to_video`、`image_to_video` 或 `reference_video` 能力的模型。
- `audio`：具有 `text_to_audio` 能力的模型。

同一供应商模型可以在多个分类中出现。策略项以 `(provider_id, model_id)` 唯一标识，不能只用 `model_id`，避免不同供应商同名模型冲突。

## 后台页面设计

### 页面位置

在后台“设置 / 模型”页面的“默认向量模型”模块下方增加“AIGC 创意工作室模型”卡片。

卡片内按以下顺序纵向排列四个配置块：

1. 生文模型
2. 生图模型
3. 生视频模型
4. 生音频模型

四块采用纵向布局，不使用四列并排，确保长模型名、多供应商和窄屏场景有稳定空间。

### 固定结构与大量模型处理

每个配置块包含：

- 标题、说明、当前启用数量和独立保存按钮；
- 支持搜索的“添加模型”下拉框；
- 单独展示的默认模型行；
- 最多三行的已启用模型摘要；
- “展开管理”入口，打开固定高度的抽屉管理完整列表。

下拉框按供应商分组并使用虚拟滚动。选项展示供应商名称、模型名称、模型 ID 和状态。模型数量增加不会撑高主页面。

抽屉内部固定高度并滚动，支持：

- 搜索已选模型；
- 拖拽排序；
- 设置默认模型；
- 移除模型。

设置默认模型时，该模型同时移动到有序白名单第一项。数据层仍显式保存默认模型，不依赖接口或名称排序。

### 候选模型状态

后台候选接口返回完整相关模型库存。不可用模型仍可见，但灰色禁用并显示一个或多个原因：

- `unpriced`：未定价；
- `unpublished`：未发布；
- `provider_unconfigured`：供应商未配置；
- `provider_disabled`：供应商已停用；
- `adapter_unsupported`：暂不支持 AIGC。

该展示规则同时应用于现有默认 LLM、默认向量模型和新增 AIGC 模型配置。搜索可以命中不可用模型，使管理员能够判断模型存在但不可选的原因。

已保存在策略中、后来失效的模型继续出现在已选列表并标明原因。管理员可以移除它，但不能重新将其设为默认。

### 保存规则

四个分类独立保存，避免修改一个分类时覆盖其他分类。保存按钮展示未保存状态。

默认规则：

- 正常启用的分类至少包含一个当前有效模型；
- 默认模型必须属于已选列表且保存时当前有效；
- 新加入白名单的模型必须当前可选；
- 已经失效的历史选项允许保留或删除；
- 若未来允许关闭整个分类，必须增加显式“停用该类型”开关和二次确认，不能用空列表隐式表达停用。

## 数据存储

新增平台级 AIGC 模型策略存储。每个分类保存有序模型列表和显式默认模型，并记录配置元数据。

逻辑结构：

```json
{
  "category": "image",
  "configured": true,
  "version": 3,
  "models": [
    {
      "provider_id": "mxapi",
      "model_id": "gpt-image-2",
      "sort_order": 0,
      "is_default": true
    },
    {
      "provider_id": "volcengine",
      "model_id": "seedream-5",
      "sort_order": 1,
      "is_default": false
    }
  ],
  "updated_at": "2026-09-06T00:00:00Z",
  "updated_by": 1
}
```

模型名称、供应商名称、定价和发布状态不复制到策略表；读取时从实时库存关联，避免缓存状态过期。

建议使用策略主表与策略项表：

- 策略主表：分类、是否已配置、版本、更新时间、更新人；
- 策略项表：策略 ID、供应商 ID、模型 ID、排序值、是否默认；
- 对 `(policy_id, provider_id, model_id)` 建唯一约束；
- 每个策略最多一个 `is_default = true`；
- 更新策略时使用事务和乐观版本校验。

## 有效性计算

系统动态计算某分类的当前有效模型：

```text
当前有效模型
= 管理员该分类白名单
∩ 当前供应商和模型库存
∩ 当前发布目录
∩ 当前有效定价目录
∩ 当前 AIGC 能力与适配器支持
```

未创建任何策略时，不应用白名单交集，保持上线前行为：所有当前有效模型均可用。管理员第一次成功保存任一分类后，仅该分类进入白名单模式；其他尚未配置的分类继续使用兼容模式。

## 默认模型与动态回退

策略保存的默认模型称为 `configured_default`。运行时实际采用的模型称为 `effective_default`。

计算规则：

1. `configured_default` 当前有效时，直接作为 `effective_default`；
2. 否则按白名单顺序选择第一个当前有效模型；
3. 没有有效模型时，`effective_default` 为空；
4. 不修改已保存的 `configured_default`；
5. 原默认恢复有效后，自动再次成为 `effective_default`。

后台响应同时返回两者及回退原因，以便展示：

```json
{
  "configured_default": {
    "provider_id": "mxapi",
    "model_id": "gpt-image-2"
  },
  "effective_default": {
    "provider_id": "volcengine",
    "model_id": "seedream-5"
  },
  "fallback_active": true,
  "fallback_reason": "configured_default_provider_disabled"
}
```

后台显示警告：“默认模型当前不可用，系统暂时使用 Seedream 5。”

## API 设计

### 后台完整库存

`GET /api/admin/aigc-model-policy/inventory`

返回四类完整候选模型、实时状态、当前选择和默认信息。候选项示例：

```json
{
  "provider_id": "mxapi",
  "provider_name": "MXAPI",
  "model_id": "gpt-image-2",
  "model_name": "GPT Image 2",
  "category": "image",
  "selectable": false,
  "reasons": ["unpriced"],
  "selected": true,
  "is_default": true
}
```

### 读取策略

`GET /api/admin/aigc-model-policy`

返回四类策略、版本、配置默认、有效默认和回退状态。

### 保存单个分类

`PUT /api/admin/aigc-model-policy/{category}`

请求示例：

```json
{
  "version": 3,
  "models": [
    {"provider_id": "mxapi", "model_id": "gpt-image-2"},
    {"provider_id": "volcengine", "model_id": "seedream-5"}
  ],
  "default_model": {
    "provider_id": "mxapi",
    "model_id": "gpt-image-2"
  }
}
```

后端在事务内重新读取实时库存并验证请求。版本冲突返回 `409`，前端提示管理员刷新后重试。

### 用户端能力接口

继续使用 `GET /api/user/aigc-studio/capabilities`，但在现有配置、发布、定价和适配器过滤后增加对应分类的白名单过滤。响应应包含每类有效默认信息，避免前端依赖数组顺序推断默认模型。

## AIGC 页面与运行时

### 页面加载

1. 获取当前有效模型和各分类有效默认；
2. 新节点或没有保存模型的节点使用该分类 `effective_default`；
3. 已保存模型仍有效时继续使用原模型；
4. 已保存模型失效时保留画布中的原模型标识，界面显示不可用状态，并预选当前有效默认；
5. 某分类没有有效模型时，该类节点禁用运行并提示联系管理员。

### 任务提交

后端不能信任前端模型列表。每次提交时重新检查：

- 模型属于请求能力对应的策略分类；
- 模型仍位于管理员白名单；
- 供应商、发布、定价、能力和适配器仍有效。

默认模型失效时，系统可按策略计算有效默认。用户明确选择的模型在页面打开后失效时，后端不静默替换，以免生成质量、参数与计费在用户不知情时变化；接口返回明确错误，前端提示后让用户确认切换到当前有效默认并重新提交。

## 一致性与并发

- 后台库存和保存接口共用同一个模型状态判定服务；
- 用户能力接口和任务提交校验共用同一个有效策略服务；
- 保存使用数据库事务和乐观版本控制；
- 配置更新后使相关能力缓存失效；
- 不通过后台异步任务复制发布或价格状态，读取和执行时实时求交集；
- 审计记录保存管理员、分类、变更前后模型列表和默认模型。

## 错误处理

- 保存时没有有效模型：`422`，返回分类和具体原因；
- 默认不在白名单：`422`；
- 新增不可选模型：`422`，返回模型状态原因；
- 版本冲突：`409`；
- 运行时模型不再允许：明确的策略校验错误，不进入供应商调用和计费；
- 某类没有有效模型：用户端显示管理员配置提示，不使用跨分类模型回退。

## 测试策略

### 后端

- 模型分类与完整候选库存；
- 未定价、未发布、供应商未配置、供应商停用和适配器缺失状态；
- 四类策略独立保存、排序、默认唯一性和版本冲突；
- 未配置策略时的兼容行为；
- 白名单过滤；
- 默认失效、顺序回退和恢复；
- 旧节点模型失效时的提交拒绝；
- 未授权模型不能绕过前端直接提交；
- 策略保存和提交校验不会产生错误计费。

### 前端

- 四张固定结构卡片和窄屏布局；
- 大量候选模型时的搜索、分组与虚拟滚动；
- 不可选原因标签与禁用行为；
- 已选摘要、管理抽屉、排序、设默认和移除；
- 每类独立保存与版本冲突提示；
- 默认回退警告；
- AIGC 节点只显示有效白名单模型；
- 新节点默认模型、旧节点保留与失效提示；
- 默认 LLM 和向量模型选择器统一展示未定价、未发布状态。

## 上线与回滚

1. 先部署数据库结构和兼容读取逻辑；
2. 未配置策略时保持现有全部有效模型可用；
3. 部署后台配置页面；
4. 管理员按分类逐一保存，逐类进入白名单模式；
5. 观察能力接口、策略拒绝和模型回退日志；
6. 如需回滚，关闭策略过滤功能开关即可恢复兼容模式，保留策略数据以便再次启用。

该上线顺序不会在部署瞬间清空现有 AIGC 模型，也不会修改历史画布数据。
