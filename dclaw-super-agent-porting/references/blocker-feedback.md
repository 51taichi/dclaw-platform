# 卡点回传与维护方审核

本工作区把专家项目和开发 Skill 一起维护在当前 monorepo。旧 Skill 仓库的 Issue、PR、候选分支和定时拉取流程不适用于此副本。卡点证据先留在对应专家项目；可共享的脱敏摘要交本工作区维护方审核，确认通用缺口后直接在共享 `main` 更新本 Skill。未经用户授权，不向其他仓库、实例或协作者发送材料。

## 何时记录

实际步骤因失败、权限、合同缺口、工具结果不符、等待外部处理、需要绕行或状态不明而不能按原路径继续时记录。已完成但明显产生多余成本的步骤也记录，例如重复索取已知信息、缺少可执行下一步或无依据的重复测试。Node 内子步骤、首次 Skill 使用、认证下载、Schema 校验、能力授权、真实调用、产物和发布回读都适用。普通顺利完成的步骤和未执行的设想不单独记录。

DClaw 试跑的每次错误或异常回执先作为一次发生记录；同一根因可归入同一卡点，不因关联 ID 数量重复建项。不同失败阶段或根因分别记录。不能只凭错误文案断言 Skill、专家、插件或平台归属。

## 项目内证据

每条卡点保存稳定本地编号，以及以下最小事实：

- 专家 ID、版本与实际 Release，模式、Node 和子步骤；
- 发生时间、尝试次数、预期条件、可安全描述的实际条件和稳定错误码；
- 关联的任务、流程、节点、调用与恢复结果；未取得的字段明确标记；
- 已核对的正式合同版本、运行环境版本及证据位置；
- 当前状态、暂定归属和依据、下一动作与执行者。

完整关联 ID 只留在有权限的当前项目记录中，供目标实例诊断使用。共享摘要只保留必要的结构事实、次数和安全错误类别，不包含客户正文、模型输出、凭据、私钥、签名包或原始发布回执。无法安全脱敏时不传播，记录待审核范围和原因。

## 审核与修订

维护方收到节点摘要或卡点后，当次核对当前项目记录、目标实例的正式标准与工具链、Skill 当前版本和已有同类案例。给出 `通用 Skill 缺口`、`专家项目问题`、`插件或平台问题`、`外部环境`、`证据不足或多层` 的结论及依据；已接收不等于已审核。平台或专家问题也保留观察记录，检查 Skill 的诊断和续接引导是否遗漏，但不自动改成通用规则。

发现 Skill 规则过严时，找出正式合同或明确项目约束；一个同条件、可复核的反例即可触发修订，不需要重复付费或有副作用的调用。修订只收窄无依据的限制，不把单个专家的成功路径强加给所有专家。平台公开合同变化时同步受影响的 Skill 规则、Node 门槛与测试；更新版本记录，说明依据、受影响路径和旧已签名专家的兼容结论。Skill 更新本身不会修改、重签或激活专家。

进入 Git 提交阶段前遵守根目录 `AGENTS.md`：核对共享工作树，序列化 Git 写操作，只暂存本任务文件，不改写历史或覆盖其他会话。Skill 验证通过后将源文件提交到当前 `main`；发布专家和部署 EC 是独立动作，分别核对其授权与回执。

## 补漏检查

维护方和专家责任会话在项目安全停点检查尚未审核或最终回执已变化的卡点。可配置定时巡检，但不以巡检替代当次处理。按项目和卡点编号去重，记录已覆盖的时间段、未取得的材料、补充证据和下一动作；无法读取的范围标记未核，恢复后补查。没有新卡点或状态变化时保持安静。
