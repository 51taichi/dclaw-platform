# Information Design Reference

Use this reference before building data, chart, table, process, architecture, comparison, roadmap, operating model, or evidence-heavy slides.

## Core Standard

Information design turns complexity into a decision. A premium deck does not merely beautify data or diagrams; it makes the audience understand what matters, why it matters, and what action follows.

## Evidence First

For each evidence slide, define:

- decision question
- claim
- evidence source
- proof object: chart, table, diagram, screenshot, metric, case, quote, or comparison
- key takeaway
- caveat or missing proof
- annotation strategy

Do not invent values, baselines, labels, screenshots, or customer proof.

## Chart Rules

Before drawing a chart, choose the chart by the comparison task:

- change over time: line, slope, area, timeline
- ranking: bar, ordered list, lollipop
- composition: stacked bar only when parts matter; avoid decorative pies
- relationship: scatter or matrix
- progress: milestone, funnel, gauge only when honest
- variance: waterfall, before/after, delta callout

Every chart needs:

- one takeaway headline
- visible source or assumption note when needed
- intentional scale and axis treatment
- highlighted signal, muted context
- limited series and labels
- annotation that explains the decision implication

## Table Rules

Tables are acceptable when precision matters. They need:

- strong row/column hierarchy
- grouping or banding
- highlighted decision cells
- abbreviated labels
- clear units and notes
- enough spacing to read at presentation size

If the audience needs a conclusion, use a visual summary before or above the table.

## Diagram Rules

For process, architecture, operating model, and service-system slides, define:

- topology: linear, loop, hub-and-spoke, layered stack, matrix, swimlane, ecosystem, funnel, roadmap, or map
- node hierarchy
- connector logic
- directionality
- interaction between modules
- what is native editable versus raster atmosphere
- how the diagram reveals over time

Avoid default lines, generic arrows, equal cards, and decorative nodes that do not clarify relationships.

## Screenshot And UI Evidence Rules

If using screenshots:

- use real provided screenshots or clearly label placeholders
- crop around the decision-relevant area
- add native editable callouts
- avoid fake UI as evidence
- keep screenshot text legible or treat it as visual context only

## QA Checks

Score each information-heavy slide:

- decision clarity
- evidence honesty
- chart/diagram choice
- annotation usefulness
- visual hierarchy
- density control
- source fidelity
- editability

Redesign when the viewer cannot state the takeaway in one sentence, when the graphic style hides the evidence, or when a diagram looks impressive but does not explain the system.

## Failure Patterns

- chart chosen for decoration rather than comparison task
- diagram has no topology, only boxes and arrows
- process arrows look like default PowerPoint controls
- table is pasted as dense text with no decision hierarchy
- data lacks source, caveat, or assumption note
- fake screenshots imply proof that does not exist
- metric cards do not explain why the number matters
