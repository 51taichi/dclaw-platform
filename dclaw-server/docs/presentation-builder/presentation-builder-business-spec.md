# Presentation Builder 业务能力文档

日期：2026-06-26  
定位：面向技能市场和对话式工作流的“可编辑 PPT 视觉设计师”，能力对标 Codex presentations，但以 QwenPaw/DClaw 自有实现交付。

## 业务结论

用户要的不是“能生成一个 PPT 文件”，而是 Codex presentations 那种完整体验：

1. 用户上传资料或说明目标。
2. 系统提炼故事线和商业重点。
3. 系统生成多个视觉方向，并在对话正文里直接展示图片。
4. 用户选择视觉方向。
5. 系统用选中的方向、素材、布局库生成可编辑 PPT。
6. 系统渲染检查，保证图片用上、文字不重叠、PPT/PDF 是主产物。
7. 用户拿到可商用、可修改、可演示的 PPTX/PDF。

所以这个技能在技能市场里的卖点应是 **“从资料到可编辑商业级 PPT 的完整生产线”**，不是普通文件转换工具。

## 目标用户

| 用户 | 高频场景 | 价值 |
| --- | --- | --- |
| 销售 / 售前 | 客户方案、产品介绍、服务建议书 | 快速产出客户可看的方案 |
| 咨询 / 解决方案 | 战略规划、实施路线、架构方案 | 把复杂材料变成结构化表达 |
| 企业运营 | 月报、复盘、培训、制度宣导 | 降低 PPT 制作成本 |
| 创业团队 / 管理者 | 融资 BP、项目路演、商业计划 | 快速形成专业表达 |
| 内部知识团队 | 文档转课件、流程手册、培训材料 | 让沉淀内容可传播 |

## 技能市场定位

建议名称：

- 可编辑 PPT 视觉设计师
- 商业 PPT 生成与视觉增强
- Presentation Builder Pro

建议简介：

> 将文档、资料、想法或旧 PPT 转换为可编辑的商业级演示文稿。支持视觉方向选择、图片生成、80 类布局策略、图表表格、模板复刻、渲染质检和 PPTX/PDF 交付。

建议分类：

- 开发工具：否。
- 生活服务：否。
- SkillHub / 办公效率 / 商业文档：是。
- 企业服务 / 咨询方案 / 内容生产：是。

## 核心业务能力

| 能力 | MVP 表现 | 目标表现 |
| --- | --- | --- |
| 内容理解 | 根据用户描述生成页面 | 能从 PDF/PPT/Word/长文档提炼故事线 |
| 视觉方向 | 可能生成图，但对话内展示不稳定 | A/B/C 视觉方案在对话正文可见，可点击放大 |
| 用户选择 | 文本选择 | 视觉缩略图 + 选项选择 |
| 布局库 | 约 13 类布局 | 80 套 registry 化布局 |
| 图片使用 | 有时作为产物出现，但未进入 PPT | 选中方案图和素材必须映射到 slide slot |
| PPT 可编辑 | 基础文本/形状可编辑 | 文本、形状、图片、表格、图表均尽量原生可编辑 |
| 模板复刻 | 已有初步 template_path / frame_map | 能稳定读取模板、替换内容、保持风格 |
| 质量检查 | 有初步媒体/渲染检查 | final delivery 默认渲染、检查、失败重试 |
| 产物分类 | 图片可能挤占主产物 | PPTX/PDF 主产物优先，过程图片折叠为支撑资产 |
| 刷新一致性 | 刷新后显示可能变化 | 产物类型、排序、对话图片持久一致 |

## 用户旅程

### 1. 任务开始

用户输入：

- “把这个 PDF 做成客户提案 PPT”
- “重新生成 PPT，走实施路线图风格”
- “用这几张图生成一个视觉增强版”
- “按这个模板改成我们的公司方案”

系统应先确认或自动判断：

- 是否需要视觉方向选择。
- 是否需要沿用模板。
- 是否最终交付 PPTX/PDF。
- 是否必须使用用户上传图或 imagegen/GPT Image2 生成图。

### 2. 视觉方案选择

如果是商业级视觉 PPT，系统应先生成 2-4 个视觉方向：

| 方案 | 展示方式 | 用户动作 |
| --- | --- | --- |
| 方案 A | 对话正文显示缩略图 | 点击放大，回复 A/1/选择 A |
| 方案 B | 对话正文显示缩略图 | 点击放大，回复 B/2/选择 B |
| 方案 C | 对话正文显示缩略图 | 点击放大，回复 C/3/选择 C |
| 重新生成 | 文本选项 | 换一批方向 |

业务要求：

- 这些图片必须出现在对话正文，不只是右侧产物。
- 刷新后仍能在历史消息中看到。
- 这些图片也可以作为 supporting asset，但不能替代 PPT/PDF 主产物。

### 3. PPT 生成

用户选择方向后，系统进入最终 PPT 生成：

1. 抽取故事线。
2. 按页面意图选择布局。
3. 把内容映射到 title/body/stat/table/image slots。
4. 把视觉方向图拆解成背景、图标、关键视觉或风格参考。
5. 生成 PPTX。
6. 渲染每页预览。
7. QA 不通过则自动重排、拆页或换布局。
8. 交付 PPTX/PDF。

### 4. 交付与产物展示

任务完成后，产物应分层：

| 层级 | 类型 | 示例 |
| --- | --- | --- |
| 主产物 | PPTX/PDF | `xxx_视觉增强版.pptx`, `xxx.pdf` |
| 对话预览 | 视觉方案图、关键页面缩略图 | 方案 A/B/C、最终 contact sheet |
| 支撑资产 | 生成图、背景图、图标、QA 截图 | `media/imagegen/*.png` |

右侧制品区排序：

1. PPTX。
2. PDF。
3. 最终预览 contact sheet。
4. 视觉方案图。
5. 支撑图片。

这样用户刷新页面后不会看到“全是图片”，也不会误以为 PPT 没生成。

## 模型与工具要求

这个技能对大模型和工具链有要求：

| 能力 | 要求 |
| --- | --- |
| 长上下文理解 | 能读完整文档、保持故事线一致 |
| 工具调用 | 能多轮调用 imagegen、presentation_builder、send_file |
| 结构化输出 | 能输出 slide specs、layout intent、asset mapping |
| 视觉判断 | 能解释视觉方案差异并推荐 |
| 自我修复 | 能根据 QA 结果重排、拆页、换布局 |
| 图片生成 | 需要 GPT Image2/imagegen 作为视觉方向和素材来源 |
| 文件生成 | 需要后端 PPTX/PDF/预览渲染能力 |

普通轻量模型可以做“简单 PPT 草稿”，但要稳定做到商业级 PPT，需要更强的模型负责规划、选版式、映射素材和根据 QA 反馈修复。

## 和 Codex presentations 对齐的能力定义

我们要对齐的是这些结果：

| Codex 能力 | QwenPaw 目标 |
| --- | --- |
| 80 套布局库 | 自研 80 套 registry 化布局 |
| Artifact Tool compose | 自研 compose/layout DSL 或 JS sidecar |
| 可编辑 PPT 对象 | 保持文本、形状、图片、表格、图表可编辑 |
| 导入/编辑 PPTX | 支持模板复刻和局部替换 |
| 渲染 preview | 生成 slide PNG、contact sheet、PDF |
| inspect/resolve | 生成对象树和 QA 定位 |
| visual scheme selection | 对话内缩略图选择 |
| strict QA | final delivery 默认检查并失败重试 |

我们不对齐的是 Codex 私有源码本身。业务上用户感知的是能力、质量和流程，不是底层包名。

## 关键验收场景

### 场景 A：资料生成客户方案

输入：PDF/Word/长文本。  
输出：12-20 页客户方案 PPTX + PDF。  
验收：

- 有封面、目录、问题、洞察、方案、架构、路线图、价值、案例、收尾。
- 不同页面使用不同布局。
- 字号不挤、没有重叠。
- PPTX 可编辑。

### 场景 B：视觉方向选择后生成

输入：用户要求“先给我三个视觉方向”。  
输出：对话正文展示 3 张图，用户选择后生成 PPT。  
验收：

- 图在对话正文可见。
- 点击可放大。
- 选中风格进入最终 PPT。
- 支撑图不会覆盖 PPTX/PDF 主产物。

### 场景 C：沿用模板生成

输入：用户上传旧 PPT 或模板。  
输出：保留模板风格的新 PPT。  
验收：

- 字体、颜色、页眉页脚、母版风格尽量保留。
- 替换内容后不破版。
- 图片替换后能正常引用。

### 场景 D：最终交付 QA

输入：用户说“最终版”“发给客户”“重新生成完整 PPT”。  
输出：PPTX/PDF/预览。  
验收：

- 自动开启 strict QA。
- 渲染页数和 PPT 页数一致。
- 必须使用的图片全部进入 PPT。
- 有 QA 摘要。

## 业务指标

| 指标 | 目标含义 |
| --- | --- |
| 首版可用率 | 用户第一次生成后不用大改即可演示 |
| 必选素材使用率 | 用户指定/选择的图片真正进入 PPT |
| QA 通过率 | final delivery 自动检查通过 |
| 版式多样性 | 不是全篇重复两栏或卡片 |
| 手工修改时间 | 用户从资料到可演示 PPT 的时间减少 |
| 刷新一致性 | 页面刷新后主产物和对话图片不丢、不乱序 |

## 版本路线

### M0：当前文档与边界

- 明确 Codex 是能力参考，不复制私有实现。
- 明确主能力：80 布局、Artifact-like runtime、视觉选择、QA、产物分类。

### M1：体验补齐

- 对话正文展示 imagegen/GPT Image2 结果。
- 点击图片弹窗查看。
- 产物区 PPTX/PDF 主产物优先，图片支撑化。
- 修复操作详情文字重叠。

### M2：布局库 1.0

- 当前 13 类布局 registry 化。
- 扩展到 20-40 个常用商务布局。
- 每个布局有 preview 和 slot 合约。
- selector 自动选布局。

### M3：PPT 质量闭环

- final delivery 默认 render QA。
- 必须图片未使用则失败。
- 文本过密自动拆页。
- 输出 contact sheet。

### M4：Codex 级布局库

- 80 套布局 registry。
- 完整预览库。
- 对象树 inspect。
- 图表、表格、架构图、路线图能力增强。

### M5：模板复刻与企业模板

- 稳定导入旧 PPT。
- 替换文本、图片、图表数据。
- 保留品牌模板。
- 支持企业模板库。

## 风险与边界

| 风险 | 处理 |
| --- | --- |
| 直接复制私有代码 | 不做；只做能力规格复刻 |
| PPT 只是截图 | 不允许；必须保持可编辑对象 |
| 生成图没有进入 PPT | 用 asset slot + required asset QA 拦截 |
| 图片太多污染制品区 | artifact 分类和排序解决 |
| 模型选错布局 | registry + selector + QA 反馈修复 |
| 视觉很美但内容不完整 | 内容完整性优先，必要时拆页 |
| 模板复刻破版 | 先做可审计 frame map，再做自动编辑 |

## 对外表达

可以对用户这样描述：

> 这是一个可编辑 PPT 视觉设计师。它会先理解资料和商业目标，必要时生成多个视觉方向供选择，再基于布局库、图片素材和品牌风格生成可编辑 PPTX/PDF。系统会在交付前渲染检查，尽量避免图片未使用、文字重叠、页面破版等问题。

内部研发要记住：

> 用户最终判断的是“这份 PPT 能不能直接拿去讲”。所以布局库、图片映射、渲染 QA、产物分类和对话内预览是同一条业务链路，不是互相独立的小功能。
