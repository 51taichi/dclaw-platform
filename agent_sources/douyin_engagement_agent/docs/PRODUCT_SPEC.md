# 产品行为规格

## 目标与客户

目标客户是通过 Bot Server 管理抖音互动任务的运营人员。超级专家把严格协议输入
转换为可由 Bot Server 二次校验的 JSON 决策，覆盖评论规划和私信处理，但不执行
任何抖音动作。

## 支持范围

| 操作 | 输入 | 输出 | 完成判据 |
|---|---|---|---|
| `HEALTH_CHECK` | 合法三段协议 | 固定能力版本对象 | 精确等于 `{"ok":true,"capabilityVersion":"2"}` |
| `GENERATE_PLAN` | 系统数量、层级、时间窗与业务目标 | 评论树 | 数量、父子层级、时间窗和父先子后全部通过校验 |
| `REPAIR_PLAN` | 原剧本、问题清单与系统规则 | 修复后的评论树 | 与生成剧本相同，且尽量保留合法意图 |
| `GENERATE_RECOVERY` | 丢失依赖和附近评论 | 一条可执行恢复回复 | 选择真实附近评论，或降级为新一级评论 |
| `ROUTE_PRIVATE_MESSAGE` | 入站消息、同会话历史、候选任务 | 归因决定 | 只选择原候选，且概率与置信差达到该候选阈值 |
| `GENERATE_PRIVATE_REPLY` | 当前会话、目标与业务要求 | 回复或不回复决定 | 纯文本、安全、最多 1000 字，且符合目标送达状态 |
| `EVALUATE_LEAD_RULE` | 线索规则与真实入站历史 | 命中与逐字证据 | 证据消息和线索值可在真实入站消息中逐字定位 |

## 不支持范围

- 发布评论、发送私信、登录抖音、控制 Android Bot。
- Bot 筛选、配额、调度、幂等落库、审计和告警。
- 自由对话、未知操作、文件、浏览器、网络、MCP 或本地执行。
- 跨客户或跨会话记忆。

## 流程与状态

每轮只有 `received -> parsed -> model_candidate -> validated -> completed` 或
`received -> rejected/failed`。健康检查跳过模型候选。模型输出是候选；只有合同和
业务不变量校验通过后才可调用 `runtime.complete`。首次候选不合法时允许一次定向
修复，第二次仍失败则调用 `runtime.fail`。

本专家没有外部副作用或持久业务状态。同一输入重放只会重新生成候选，不会重复
收费之外的业务动作；真正的任务幂等由 Bot Server 负责。

## 人工介入

本专家本身不产生人工检查点。归因证据不足时返回 `UNRESOLVED`，由 Bot Server
进入中性澄清流程。协议错误或两次候选都无效时返回稳定失败，由调用方修正输入或
显式重试。

## 成功案例

1. 按 2 个一级、2 个二级、1 个三级节点生成五条评论，全部位于窗口内且父节点更早。
2. 原二级评论引用不存在的父节点，修复后引用有效一级节点并保持原意图。
3. 私信包含与一个候选任务一致的视频线索，概率和置信差同时超过候选阈值，返回该 `taskId`。

## 失败、重试与恢复

- 缺段、重复段、未知操作或超长消息：失败关闭，不调用模型。
- 模型返回 Markdown、额外字段、伪造候选或伪造证据：首次修复，仍不合法则失败。
- 模型服务不可用：不重试副作用，返回 `model_unavailable` 诊断引用。
- 会话上下文不可用：返回 `session_context_unavailable`。
- 归因低于阈值或候选接近：返回 `UNRESOLVED`，不得猜测。
- 断线后由平台按原 invocation 处理；专家不维护仅存在于进程内的恢复状态。

## 已知限制

源材料没有定义除 `startsAt`、`endsAt`、节点数量和层级之外的风控字段名称；当前
版本只对源材料可确认的不变量做确定性校验，其他系统规则通过模型提示执行。该项在
`SOURCE_BEHAVIOR_SPEC.md` 标记为 `unknown`，不得宣称已确定性覆盖。
